# История изменений

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии — [semver](https://semver.org/lang/ru/): MAJOR — несовместимые изменения данных или поведения, MINOR — новые функции, PATCH — исправления.

## [2.1.1] — 2026-11-23

### Безопасность

- Вход в OneDrive, Google Drive и др. (Настройки → Хранилища): параметры из запроса передаются rclone только как данные. Раньше пользователь веб-интерфейса мог подставить вместо имени параметра ключ rclone, например `--log-file`, и записать файл в произвольное место от имени службы. Нужен был вход в программу.
- `/api/health` (доступен без пароля) больше не показывает путь к папке данных и текст ошибки ОС; они пишутся в журнал.

## [2.1.0] — 2026-11-23

Первая публичная версия.

### Новое

- **Импорт устройств из CSV:** «Добавить устройство» → «📥 Импорт из CSV». Сначала показывает, что будет добавлено, и только после подтверждения сохраняет. Разделитель «;» или «,», UTF-8 или Windows-1251, русские и английские названия колонок, образец файла. Дубликаты и занятые папки бэкапов не добавляются. Сеть не сканируется.
- **Шапка:** вместо плашек «Служба…» и «Автобэкап…» — значок режима запуска (Docker, служба Linux или Windows, приложение, скрипт), состояние планировщика со временем запуска и сводка устройств: всего, актуальных, с ошибкой, просроченных, отключённых. Счётчики ведут на главную с фильтром.
- **Лицензия AGPL-3.0.** В подвале всех страниц — версия, ссылки на текст лицензии, исходный код и список сторонних компонентов. `THIRD_PARTY_LICENSES.txt` — в установщике и Docker-образе.

### Изменено

- Кнопка «⚙ Настройки» сразу открывает вкладку «Общие», без выпадающего меню.
- `--version` выводит также авторские права и лицензию; номер версии — в первой строке.
- Новый значок программы.

### Исправлено

- Главная: статус устройства, карточка и счётчики фильтров обновляются после бэкапа без перезагрузки страницы, в том числе после бэкапа по расписанию или из другой вкладки.

## [2.0.0] — 2026-11-19

### Важно при обновлении с 1.x

- **Устройства переезжают в `data/devices.json`** (раньше были в `plugins/<Тип>/routers.json`), SSH-ключи — в `data/keys/<тип>/`, ключ шифрования паролей — в `data/secret.key`. При первом запуске это делается автоматически; копия старых файлов остаётся в `data/migration-backup-<дата>/`.
- **Адреса страниц устройства** теперь по постоянному id: `/device/<id>/…`. Закладки на старые адреса `/…/<тип>/<номер>` не работают.
- **Минимальные требования:** Windows 10, Python 3.11 (при запуске из исходников).
- Плагины устройств сторонних авторов должны объявить описание `PLUGIN` (контракт v1, [docs/PLUGINS.md](docs/PLUGINS.md)), иначе не загружаются.

### Новое

**Установка и запуск**
- **Docker:** образ для amd64 и arm64 в `ghcr.io/ser-zhur/networkbackupmanager`, `docker-compose.yml`; можно и собирать на сервере. Обновление — `docker compose pull && docker compose up -d`. [docs/DOCKER.md](docs/DOCKER.md).
- **Linux без Docker:** `sudo ./install.sh` — служба systemd от отдельного пользователя `nbm`, повторный запуск обновляет, неудачное обновление откатывается само, `--uninstall`. [docs/LINUX.md](docs/LINUX.md).
- **Установщик Windows** собирается и проверяется в GitHub Actions и прикладывается к релизу.
- Папка данных задаётся `NBM_HOME`; её можно перенести в другое место, на другой компьютер или в Docker — пути бэкапов находятся сами.
- Настройки через переменные окружения `NBM_*` (адрес, порт, первый пользователь, прокси, rclone, токен мониторинга); первый пользователь создаётся без окна (`NBM_ADMIN_USER` / `NBM_ADMIN_PASSWORD`).

**Устройства**
- **Универсальный SSH-плагин:** профили Cisco IOS, D-Link DGS, Huawei VRP, HPE Comware / H3C, Aruba OS-Switch, Juniper Junos, VyOS / EdgeOS, OpenWrt; свои профили — JSON в `data/ssh_profiles/`; «свои команды» прямо в настройках устройства. Вывод проверяется: оборванный или ошибочный не затирает прежнюю версию.
- **Контракт плагинов v1:** плагин описывает себя (название, способ входа, свои поля) — формы добавления и правки строятся по описанию; общий SSH-помощник `core/ssh.py` для авторов плагинов.

**Уведомления** (Настройки → Уведомления)
- Telegram, почта (SMTP), webhook (Slack, Mattermost, Rocket.Chat и свой обработчик).
- Об ошибках бэкапа и выгрузки, восстановлении, изменениях конфигурации (файлы и число строк, по желанию — текст изменений), итогах прогона, запуске программы. За прогон всех устройств — одно сообщение.
- Повтор при сбое сети, кнопка «Проверить», секреты каналов хранятся зашифрованными.

**Мониторинг** (Настройки → Мониторинг)
- `GET /api/health` (без пароля), `GET /api/status` и `GET /api/events` (по токену): состояние устройств и планировщика, проблемы, журнал событий.
- Готовый шаблон Zabbix 6.0+ с обнаружением устройств и триггерами.
- Журнал событий `data/events.jsonl`.

**Состояние устройств**
- У каждой попытки бэкапа запоминается исход: время, ошибка, число неудач подряд. В карточке — «последняя успешная связь» и причина последней ошибки.

### Изменения

- Бэкап одного устройства и прогон всех устройств выполняются одним кодом; прогон, прерванный по общему тайм-ауту, засчитывается как неудача.
- Сообщение «SSH-ключ не найден» показывает, куда положить ключ (`data/keys/<тип>/`).
- Вкладка «Служба» учитывает, кто управляет программой: Docker, systemd (`install.sh`) или сама программа.

### Исправления

- В списке типов на странице добавления устройства был виден только выбранный тип.
- Выгрузка во внешнее хранилище, восстановившаяся после пропущенной попытки, не отмечалась как восстановление.
- Установщик Windows: при обновлении оставались библиотеки прежней сборки; тихая установка и удаление могли ждать окон; шаги удаления данных прежних версий не работали.

## [1.1.0] — 2026-11-18

Первая версия с единым номером. Бэкап MikroTik (RouterOS 6/7), pfSense и D-Link DGS-1510 по SSH; история версий в git с просмотром изменений; внешние хранилища через rclone с шифрованием 7z; расписание и очистка старых версий; служба Windows и systemd; веб-интерфейс с тегами, избранным, поиском и фильтрами; защита от CSRF, проверка ключей хоста SSH.
