# Плагины устройств

Для этого документа есть два пути:

- **Устройство отдаёт конфигурацию командой по SSH.** Плагин не нужен: достаточно [профиля SSH](#профили-ssh), JSON-файла с командами.
- **Нужна своя логика.** Например, скачать файл по SFTP, выполнить несколько шагов или узнать версию прошивки. Тогда пишется плагин по [контракту v1](#контракт-v1).

## Профили SSH

Профиль — файл `data/ssh_profiles/<id>.json`. `<id>` — латиница, цифры и `_`; `custom` зарезервирован. Профили из поставки лежат в `plugins/SSH/profiles/` и служат примерами. Свой файл с тем же `<id>` заменяет поставочный. Профили читаются при запуске программы; ошибка в профиле пишется в лог, и такой профиль пропускается.

```json
{
  "name": "Cisco IOS / IOS-XE",
  "description": "show running-config",
  "mode": "shell",
  "enable": "enable",
  "setup": ["terminal length 0"],
  "default_username": "admin",
  "commands": [
    {
      "command": "show running-config",
      "file": "running-config.cfg",
      "start": "^(Building configuration|Current configuration)",
      "end": "^end\\s*$",
      "drop": ["^! Last configuration change at", "^ntp clock-period"]
    }
  ]
}
```

| Поле | Обязательно | Назначение |
|---|---|---|
| `name` | | Название в списке профилей |
| `description` | | Подсказка |
| `mode` | | `shell` (по умолчанию): интерактивная сессия, как у человека в терминале. `exec`: каждая команда выполняется отдельно, подходит для Linux, OpenWrt и Junos |
| `setup` | | Только для `shell`: команды перед выгрузкой, например отключение постраничного вывода. Их вывод не сохраняется |
| `enable` | | Только для `shell`: команда входа в привилегированный режим. Выполняется, если приглашение заканчивается на `>`; пароль берётся из поля «Пароль enable» устройства |
| `pager` | | Регулярное выражение для приглашения постраничного вывода; на него отвечаем пробелом. По умолчанию `--More--` и похожие. `null` отключает |
| `default_username` | | Имя пользователя, если в устройстве оно не задано |
| `commands` | да | Команды выгрузки, хотя бы одна |
| `commands[].command` | да | Команда |
| `commands[].file` | да | Имя файла для вывода: латиница, цифры, `.`, `_`, `-` |
| `commands[].start` | | Регулярное выражение для первой строки конфигурации. Строки до неё отбрасываются. Если такой строки нет, это ошибка |
| `commands[].end` | | Регулярное выражение для последней строки конфигурации. Если её нет, вывод считается оборванным: это ошибка, и файл не сохраняется |
| `commands[].drop` | | Регулярные выражения для строк, которые удаляются из файла |

Регулярные выражения — синтаксис Python, они применяются к каждой строке отдельно. Обратную косую черту в JSON нужно удваивать: `\\s`.

`drop` нужен для строк, которые меняются при каждой выгрузке (время, счётчики). Иначе каждая выгрузка будет новой версией в истории. Удаляйте только комментарии и служебные строки: удалённое не попадёт в бэкап.

Перед сохранением вывод проверяется:

- если в первых строках есть `% Invalid input`, `Unknown command`, `syntax error` или похожее, устройство не приняло команду и это ошибка;
- пустой вывод — ошибка;
- файлы пишутся только после того, как выполнены все команды профиля.

### Свои команды без файла профиля

В устройстве выберите профиль «Свои команды» и перечислите команды по одной в строке. Каждая команда сохраняется в свой файл. Имя файла можно задать так: `config.txt: show running-config`. Строки, начинающиеся с `#`, пропускаются. Проверки `start`, `end` и `drop` здесь недоступны; для них нужен файл профиля.

## Контракт v1

Плагин — папка `plugins/<Имя>/` с файлом `plugin.py`. Тип устройства — имя папки в нижнем регистре. Он хранится в `data/devices.json`, поэтому после появления устройств папку не переименовывают.

```python
from core import ssh
from core.plugin_api import PluginError

PLUGIN = {
    "api": 1,
    "title": "Мой коммутатор",
    "description": "Подсказка под списком типов",
    "auth": ["password", "key"],       # какие поля входа показывать
    "default_username": "admin",
    "default_port": 22,
    "fields": [                        # свои поля устройства (необязательно)
        {"name": "vdom", "label": "VDOM", "type": "text",
         "placeholder": "root", "help": "Пусто — весь конфиг"},
        {"name": "api_key", "label": "Ключ API", "type": "password"},
    ],
}


def run_backup(device: dict) -> list[str]:
    client = ssh.connect(device)
    try:
        text = ssh.run(client, "show full-configuration")
    finally:
        client.close()
    if "config system global" not in text:
        raise PluginError("В выводе нет конфигурации")
    return [ssh.write_text(device["backup_path"], "config.conf", text)]


def normalize_for_compare(filename: str, data: bytes) -> bytes:   # необязательно
    return data
```

### `PLUGIN`

| Ключ | Назначение |
|---|---|
| `api` | Версия контракта. Сейчас `1`; плагин с другой версией не загружается |
| `title` | Название типа в интерфейсе |
| `description` | Подсказка |
| `auth` | `password` и/или `key`: какие поля входа показывать в форме |
| `default_username`, `default_port` | Подставляются в форму нового устройства |
| `fields` | Свои поля устройства |
| `setup` | Как подготовить устройство: список шагов (строк). Форма добавления показывает их, когда выбран этот тип, форма редактирования — свёрнутыми. Текст в обратных кавычках (`` `nbm-backup` ``) выводится моноширинным |

Если в `auth` есть `key`, под полем ключа в форме появляется кнопка **«Создать пару ключей»**. Она создаёт RSA-ключ 2048 бит в `data/keys/<тип>/<имя>` (PEM без пароля) и показывает открытый ключ, чтобы вставить его на устройство. Существующий файл кнопка не перезаписывает, а показывает его открытый ключ. Пример шагов `setup` — в `plugins/Pfsense/plugin.py`.

Свойства поля в `fields`:

- `name`: латиница в нижнем регистре, цифры, `_`. Имена, которыми управляет ядро (`host`, `port`, `username`, `ssh_pass`, `ssh_key`, `backup_path`, `name`, `tags`, `storage` и другие), заняты.
- `label`: подпись в форме.
- `type`: `text`, `password`, `number`, `select`, `textarea` или `checkbox`.
- `required`: поле обязательно.
- `default`: значение по умолчанию.
- `choices`: для `select`, список `[значение, подпись]`.
- `help`, `placeholder`: подсказки в форме.

Поля `password` хранятся зашифрованными и в форму не выводятся.

Плагин, нарушающий контракт, не загружается. Причина пишется в лог и показывается на странице добавления устройства.

### `run_backup(device)`

`device` — копия настроек устройства:

| Ключ | Что содержит |
|---|---|
| `host`, `port`, `username` | Адрес, порт и имя пользователя |
| `ssh_pass` | Пароль, уже расшифрованный |
| `ssh_key` | Абсолютный путь к ключу в `data/keys/<тип>/`. Файла может не быть |
| `backup_path` | Абсолютный путь к рабочему каталогу устройства, куда пишутся файлы |
| свои поля | Значения из `fields`; поля `password` уже расшифрованы |

Возвращаемое значение:

- список путей к файлам конфигурации в `backup_path`. Ядро сохраняет их в git-историю устройства и во внешние хранилища;
- `[]` — успех, выгружать нечего;
- ошибка — исключение. Текст `PluginError` показывается пользователю как есть, поэтому пишите его понятно. Нельзя перехватывать ошибку и возвращать `[]`: сломанное устройство будет выглядеть исправным.

`run_backup` вызывается в отдельном потоке, параллельно для разных устройств. Не используйте глобальное изменяемое состояние.

### `normalize_for_compare(filename, data)` — необязательно

Возвращает содержимое файла в виде для сравнения «изменилось или нет». Например, без строки с датой выгрузки. Сам файл сохраняется целиком. Используйте эту функцию вместо удаления строк, если строку нужно сохранить в бэкапе.

### `core.ssh` — помощник SSH

| Функция | Назначение |
|---|---|
| `ssh.connect(device, default_username=…, default_port=…)` | Подключение с ключом и/или паролем устройства. Ключ хоста запоминается при первом подключении; если он изменился, подключение отклоняется. Ошибки входа и связи превращаются в `PluginError` |
| `ssh.run(client, command, timeout)` | Выполнить одну команду (exec). Ненулевой код возврата — `PluginError` |
| `ssh.Shell(client, timeout=…, pager=…)` | Интерактивная сессия: `with ssh.Shell(c) as sh: sh.send("cmd")`. Приглашение определяется само, постраничный вывод пролистывается. Есть также `sh.enable(команда, пароль)` |
| `ssh.write_text(dir, name, text)` | Атомарная запись файла; возвращает абсолютный путь |
| `ssh.clean(text)` | Удаляет управляющие последовательности терминала и `\r` |

### Сборка EXE

`build_exe.bat` копирует в сборку `plugin.py` и `profiles/*.json` каждой папки плагина. Python-модули, которые плагин импортирует, должны входить в сборку. Модули ядра и paramiko уже входят; если нужно что-то ещё, добавьте `--hidden-import` в `build_exe.bat`.
