# Плагины устройств

Для этого документа есть два пути:

- **Устройство отдаёт конфигурацию командой по SSH или файлом (SFTP, SCP).** Плагин не нужен: достаточно [профиля SSH](#профили-ssh) — JSON-файла с командами и файлами для скачивания.
- **Нужна своя логика.** Например, сначала попросить устройство создать файл, выполнить несколько шагов или показать в форме инструкцию по подготовке устройства. Тогда пишется плагин по [контракту v1](#контракт-v1).

## Профили SSH

Профиль — файл `data/ssh_profiles/<id>.json`. `<id>` — латиница, цифры и `_`; `custom` зарезервирован. Профили из поставки лежат в `plugins/SSH/profiles/` и служат примерами. Свой файл с тем же `<id>` заменяет поставочный. Профили читаются при запуске программы; ошибка в профиле пишется в лог, и такой профиль пропускается.

```json
{
  "name": "Cisco IOS / IOS-XE",
  "description": "show running-config",
  "mode": "shell",
  "enable": "enable",
  "setup": ["terminal length 0"],
  "default_username": "admin",
  "commands": [
    {
      "command": "show running-config",
      "file": "running-config.cfg",
      "start": "^(Building configuration|Current configuration)",
      "end": "^end\\s*$",
      "drop": ["^! Last configuration change at", "^ntp clock-period"]
    }
  ]
}
```

| Поле | Обязательно | Назначение |
|---|---|---|
| `name` | | Название в списке профилей |
| `description` | | Подсказка |
| `mode` | | `shell` (по умолчанию): интерактивная сессия, как у человека в терминале. `exec`: каждая команда выполняется отдельно, подходит для Linux, OpenWrt и Junos |
| `setup` | | Только для `shell`: команды перед выгрузкой, например отключение постраничного вывода. Их вывод не сохраняется |
| `enable` | | Только для `shell`: команда входа в привилегированный режим. Выполняется, если приглашение заканчивается на `>`; пароль берётся из поля «Пароль enable» устройства |
| `pager` | | Регулярное выражение для приглашения постраничного вывода; на него отвечаем пробелом. По умолчанию `--More--` и похожие. `null` отключает |
| `default_username` | | Имя пользователя, если в устройстве оно не задано |
| `commands` | да | Что выгружать, хотя бы один элемент: команда (`command`) или файл (`download`) |
| `commands[].command` | одно из двух | Команда; её вывод сохраняется в файл |
| `commands[].download` | одно из двух | Путь к файлу на устройстве. Файл скачивается по SFTP, если не вышло — по SCP (старый протокол, как `scp -O`), и сохраняется байт в байт |
| `commands[].file` | да | Имя файла в бэкапе: латиница, цифры, `.`, `_`, `-` |
| `commands[].start` | | Для команды — регулярное выражение для первой строки конфигурации: строки до неё отбрасываются. Для файла — проверка первой непустой строки. Нет совпадения — ошибка |
| `commands[].end` | | Для команды — регулярное выражение для последней строки конфигурации. Для файла — проверка последней непустой строки. Нет совпадения — вывод или файл оборван: ошибка, файл не сохраняется |
| `commands[].drop` | | Только для команды: регулярные выражения для строк, которые удаляются из файла |
| `commands[].ignore` | | Регулярные выражения для строк, которые не считаются изменением конфигурации. Файл сохраняется целиком, строки только не участвуют в сравнении «изменилось или нет» |

Пример профиля со скачиванием файла (из поставки, `opnsense.json`):

```json
{
  "name": "OPNsense",
  "default_username": "root",
  "commands": [
    {
      "download": "/conf/config.xml",
      "file": "config.xml",
      "start": "^<\\?xml",
      "end": "^</opnsense>$"
    }
  ]
}
```

Команды и файлы можно сочетать в одном профиле: например, `show version` для истории и файл конфигурации для восстановления. Сначала выполняются команды, затем скачиваются файлы.

Регулярные выражения — синтаксис Python, они применяются к каждой строке отдельно. Обратную косую черту в JSON нужно удваивать: `\\s`.

`drop` и `ignore` нужны для строк, которые меняются при каждой выгрузке (время, счётчики). Иначе каждая выгрузка будет новой версией в истории. `drop` удаляет строку из бэкапа — удаляйте так только комментарии и служебные строки. `ignore` оставляет строку в бэкапе и только не учитывает её при сравнении; для скачанных файлов доступен только он, чтобы файл можно было загрузить обратно в устройство.

Перед сохранением проверяется:

- если в первых строках вывода есть `% Invalid input`, `Unknown command`, `syntax error` или похожее, устройство не приняло команду и это ошибка;
- пустой вывод или пустой файл — ошибка;
- файлы пишутся только после того, как выполнены все команды и скачаны все файлы профиля; при ошибке прежние версии остаются.

### Свои команды без файла профиля

В устройстве выберите профиль «Свои команды» и перечислите команды по одной в строке. Каждая команда сохраняется в свой файл. Имя файла можно задать так: `config.txt: show running-config`. Строки, начинающиеся с `#`, пропускаются.

`file:<путь>` — скачать файл, а не выполнить команду (SFTP, затем SCP):

```
config.xml: file:/conf/config.xml
fortigate.conf: file:sys_config
version.txt: show version
```

Без имени файл сохраняется под своим именем: `file:/conf/config.xml` → `config.xml`. Проверки `start`, `end`, `drop` и `ignore` здесь недоступны; для них нужен файл профиля.

## Контракт v1

Плагин — папка `plugins/<Имя>/` с файлом `plugin.py`. Свои плагины на Linux кладут в `/var/lib/nbm/plugins/<Имя>/`, в Docker — в `nbm/plugins/<Имя>/`: папка программы при обновлении заменяется целиком, а папка данных остаётся. На Windows это та же `plugins\` в папке программы. Плагин с именем встроенного не загружается. Тип устройства — имя папки в нижнем регистре. Он хранится в `data/devices.json`, поэтому после появления устройств папку не переименовывают.

```python
from core import ssh
from core.plugin_api import PluginError

PLUGIN = {
    "api": 1,
    "title": "Мой коммутатор",
    "description": "Подсказка под списком типов",
    "auth": ["password", "key"],       # какие поля входа показывать
    "default_username": "admin",
    "default_port": 22,
    "fields": [                        # свои поля устройства (необязательно)
        {"name": "vdom", "label": "VDOM", "type": "text",
         "placeholder": "root", "help": "Пусто — весь конфиг"},
        {"name": "api_key", "label": "Ключ API", "type": "password"},
    ],
}


def run_backup(device: dict) -> list[str]:
    client = ssh.connect(device)
    try:
        text = ssh.run(client, "show full-configuration")
    finally:
        client.close()
    if "config system global" not in text:
        raise PluginError("В выводе нет конфигурации")
    return [ssh.write_text(device["backup_path"], "config.conf", text)]


def normalize_for_compare(filename: str, data: bytes) -> bytes:   # необязательно
    return data
```

### `PLUGIN`

| Ключ | Назначение |
|---|---|
| `api` | Версия контракта. Сейчас `1`; плагин с другой версией не загружается |
| `title` | Название типа в интерфейсе |
| `description` | Подсказка |
| `auth` | `password` и/или `key`: какие поля входа показывать в форме |
| `default_username`, `default_port` | Подставляются в форму нового устройства |
| `fields` | Свои поля устройства |
| `setup` | Как подготовить устройство: список шагов (строк). Форма добавления показывает их, когда выбран этот тип, форма редактирования — свёрнутыми. Текст в обратных кавычках (`` `nbm-backup` ``) выводится моноширинным |

Если в `auth` есть `key`, под полем ключа в форме появляется кнопка **«Создать пару ключей»**. Она создаёт RSA-ключ 2048 бит в `data/keys/<тип>/<имя>` (PEM без пароля) и показывает открытый ключ, чтобы вставить его на устройство, либо скачать файлом `.pub` (RouterOS 6 и Winbox принимают ключ только файлом). Существующий файл кнопка не перезаписывает, а показывает его открытый ключ. Пример шагов `setup` — в `plugins/Pfsense/plugin.py`.

Свойства поля в `fields`:

- `name`: латиница в нижнем регистре, цифры, `_`. Имена, которыми управляет ядро (`host`, `port`, `username`, `ssh_pass`, `ssh_key`, `backup_path`, `name`, `tags`, `storage` и другие), заняты.
- `label`: подпись в форме.
- `type`: `text`, `password`, `number`, `select`, `textarea` или `checkbox`.
- `required`: поле обязательно.
- `default`: значение по умолчанию.
- `choices`: для `select`, список `[значение, подпись]`.
- `help`, `placeholder`: подсказки в форме.

Поля `password` хранятся зашифрованными и в форму не выводятся.

Плагин, нарушающий контракт, не загружается. Причина пишется в лог и показывается на странице добавления устройства.

### `run_backup(device)`

`device` — копия настроек устройства:

| Ключ | Что содержит |
|---|---|
| `host`, `port`, `username` | Адрес, порт и имя пользователя |
| `ssh_pass` | Пароль, уже расшифрованный |
| `ssh_key` | Абсолютный путь к ключу в `data/keys/<тип>/`. Файла может не быть |
| `backup_path` | Абсолютный путь к рабочему каталогу устройства, куда пишутся файлы |
| свои поля | Значения из `fields`; поля `password` уже расшифрованы |

Возвращаемое значение:

- список путей к файлам конфигурации в `backup_path`. Ядро сохраняет их в git-историю устройства и во внешние хранилища;
- `[]` — успех, выгружать нечего;
- ошибка — исключение. Текст `PluginError` показывается пользователю как есть, поэтому пишите его понятно. Нельзя перехватывать ошибку и возвращать `[]`: сломанное устройство будет выглядеть исправным.

`run_backup` вызывается в отдельном потоке, параллельно для разных устройств. Не используйте глобальное изменяемое состояние.

### `normalize_for_compare(filename, data)` — необязательно

Возвращает содержимое файла в виде для сравнения «изменилось или нет». Например, без строки с датой выгрузки. Сам файл сохраняется целиком. Используйте эту функцию вместо удаления строк, если строку нужно сохранить в бэкапе.

### `compare_normalizer(device)` — необязательно

То же для конкретного устройства, когда правила зависят от его настроек: возвращает функцию `(filename, data) -> data` или `None`. `None` — используется `normalize_for_compare` (если есть). Так плагин SSH применяет `ignore` из профиля устройства.

### `core.ssh` — помощник SSH

| Функция | Назначение |
|---|---|
| `ssh.connect(device, default_username=…, default_port=…)` | Подключение с ключом и/или паролем устройства. Ключ хоста запоминается при первом подключении; если он изменился, подключение отклоняется. Ошибки входа и связи превращаются в `PluginError`. Старые прошивки с SHA-1 (ключ хоста `ssh-rsa`, обмен `group1`/`group14`/`group-exchange-sha1`) тоже подключаются: эти алгоритмы идут последними. Свой `paramiko.SSHClient` в плагине — передайте `transport_factory=ssh.CompatTransport` |
| `ssh.run(client, command, timeout)` | Выполнить одну команду (exec). Ненулевой код возврата — `PluginError` |
| `ssh.Shell(client, timeout=…, pager=…)` | Интерактивная сессия: `with ssh.Shell(c) as sh: sh.send("cmd")`. Приглашение определяется само, постраничный вывод пролистывается. Есть также `sh.enable(команда, пароль)` |
| `ssh.download(client, remote, local, timeout)` | Скачать файл: SFTP, при неудаче — SCP. Возвращает `"sftp"` или `"scp"`; не удалось обоими — `PluginError` с обеими причинами |
| `ssh.write_text(dir, name, text)` | Атомарная запись файла; возвращает абсолютный путь |
| `ssh.clean(text)` | Удаляет управляющие последовательности терминала и `\r` |

### Сборка EXE

`build_exe.bat` копирует в сборку `plugin.py` и `profiles/*.json` каждой папки плагина. Python-модули, которые плагин импортирует, должны входить в сборку. Модули ядра и paramiko уже входят; если нужно что-то ещё, добавьте `--hidden-import` в `build_exe.bat`.
